# دليل التحديث (التطبيق والمشروع)

## أولاً: ثلاثة أشياء مختلفة لا تخلطها

| ماذا تحدّث | أين | النتيجة |
|---|---|---|
| **التطبيق على هاتفك** | تنزيل APK جديد من Actions وتثبيته فوق القديم | تحصل على الميزات الجديدة |
| **شيفرة المشروع** | رفع `MagicRDR-project.zip` جديد إلى المستودع | يبدأ بناء جديد تلقائياً |
| **سكربت البناء** | تعديل `.github/workflows/main.yml` | يغيّر طريقة البناء (ليس التطبيق) |

## ثانياً: دورة التحديث الكاملة (من الهاتف)

1. **احصل على الـ ZIP الجديد** (من المحادثة) واحفظه في هاتفك.
2. افتح مستودعك على github.com ← تبويب **Code**.
3. افتح الـ ZIP القديم (`MagicRDR-project.zip`) ← أيقونة سلة المهملات 🗑 ← **Commit changes**.
   لا تترك ZIP قديماً بجانب الجديد (السكربت يختار الأكبر حجماً وقد يختار القديم).
4. **Add file ← Upload files** ← اختر الـ ZIP الجديد ← **Commit changes**.
5. الدفع يشغّل البناء وحده. افتح **Actions** وانتظر 12–18 دقيقة.
6. لو استلمتَ `main.yml` جديداً أيضاً: عدّله **قبل** رفع الـ ZIP، لأن كل Commit يبدأ بناءً (والأحدث يلغي الأقدم تلقائياً).
7. بعد النجاح (✔) افتح التشغيل ← انزل إلى **Artifacts** ← نزّل `MagicRDR-android-apk` ← فكّ ضغط الملف.
8. **افتح الـ APK الناتج** (`MagicRDR-<الإصدار>.apk`) ← **تحديث/Update**. لا تحذف التطبيق القديم.

## ثالثاً: كيف تتأكد أن التحديث سيُقبل (قبل التثبيت)

افتح التشغيل ← **Summary**، وطابق:

| الحقل | يجب أن يكون |
|---|---|
| package | `com.magicrdr.mobile` (نفس القديم دائماً) |
| Signing | `permanent release key` |
| Certificate SHA-256 | `af8bd63ec56ca5feb91d788f3cd4c8a02799be6b49f7036bba4348d627bf3b8b` (نفسها في كل بناء) |
| versionCode | أكبر من السابق (يرتفع تلقائياً) |

إن اختلفت البصمة فلا تثبّت: سيرفضه أندرويد (أو سيطلب حذف القديم).

## رابعاً: أرقام الإصدار

- `versionCode` = عدد الدقائق منذ 2026‑01‑01 UTC، فيزداد في كل بناء ولا يعود للوراء أبداً.
- `versionName` = `APP_VERSION_BASE` + `.` + رقم التشغيل (مثل `1.1.12`).
- لإصدار ظاهر جديد: عدّل السطر `APP_VERSION_BASE: "1.1"` في `main.yml` (مثلاً إلى `"1.2"`).

## خامساً: ماذا يحدث لبياناتك عند التحديث؟

- **تبقى:** الأسماء المستوردة، والأرشيف المفتوح وتعديلاتك غير المحفوظة وموضعك (الجلسة)، لأن الحزمة نفسها لم تتغير.
- **تضيع:** إن حذفتَ التطبيق ثم ثبّتّه. لذلك لا تحذفه إلا اضطراراً. احفظ نسخة من أرشيفك المعدّل (Save RPF ثم احفظ الناتج) قبل أي حذف.

## سادساً: مشكلات التثبيت وحلولها

| الرسالة/العَرَض | السبب | الحل |
|---|---|---|
| «لم يتم تثبيت التطبيق لتعارض مع حزمة موجودة» | توقيع مختلف (نسخة قديمة موقّعة بمفتاح مؤقت) | احذف التطبيق القديم مرة واحدة ثم ثبّت. بعدها لن يتكرر |
| «لا يمكن تثبيت إصدار أقدم» | `versionCode` أقل | لا يحدث مع هذا النظام إلا إذا بنيتَ محلياً بإعدادات يدوية |
| «تم الحظر من Play Protect» | تطبيق من خارج المتجر | اختر «التثبيت على أي حال» |
| «التثبيت من هذا المصدر غير مسموح» | صلاحية المتصفح/مدير الملفات | الإعدادات ← السماح بتثبيت تطبيقات من مصادر غير معروفة لهذا التطبيق |
| الملف لا يفتح بعد التنزيل | الملف ما زال zip | فكّ ضغط `MagicRDR-android-apk.zip` أولاً |
| ملف APK ناقص/تالف | تنزيل مقطوع | نزّله من جديد |
| فشل البناء | سجل Actions | افتح الخطوة الحمراء وأرسل أول 20 سطراً من الخطأ |

## سابعاً: الرجوع لإصدار سابق

أندرويد لا يسمح بتثبيت إصدار أقدم فوق أحدث. لو احتجت الرجوع:
1. احفظ أرشيفك المعدّل خارج التطبيق.
2. احذف التطبيق.
3. ثبّت الـ APK القديم (من Artifacts قبل انتهاء الـ 14 يوماً).
بعدها كل التحديثات تعمل بشكل طبيعي. (لذلك نزّل نسخة من كل APK مستقر لديك.)

## ثامناً: قوائم مراجعة

**قبل رفع ZIP جديد:** نزّلتُ نسخة من آخر APK يعمل؟ احتفظتُ بكلمة مرور المفتاح ونسخة الـ keystore؟
**بعد البناء:** البصمة مطابقة؟ package صحيح؟ الاختبارات اجتازت (الخطوة Run unit tests)؟
**بعد التثبيت:** يفتح؟ يستعيد جلستي؟ جرّب على **نسخة** من أرشيف قبل أي عمل حقيقي.
